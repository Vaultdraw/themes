# Vaultdraw themes

Colour themes for [Vaultdraw](https://github.com/Vaultdraw/vaultdraw). Plain JSON palettes: data only, no code.

Your Excalidraw drawings live in a folder you own. Your themes do too: each one is a folder with one JSON file, and you can read, copy and edit it.

## Install a theme

Pick one way.

| Way | Steps |
| --- | --- |
| Settings | Settings, Appearance, **Install from URL...**, paste the theme folder URL |
| Command palette | Run **Theme: Install from URL...** |
| CLI | `vaultdraw theme install Vaultdraw/themes/<Name>` |
| Manual | Copy the `<Name>` folder into the config folder `themes/`: `~/.config/vaultdraw/themes/` on macOS and Linux |

Example: `vaultdraw theme install Vaultdraw/themes/Vesper`.

## Not here: the ten built-in themes

These ship inside the app, so they are not in this repo:

Default, Dracula, Catppuccin, Solarized, Gruvbox, Tokyo Night, Nord, Kanagawa, Everforest, One Dark.

The original community "Everforest" palette is here as **Everforest Dim**, so the names do not clash.

## Add your own theme

1. Copy an existing folder, for example `cp -r Vesper "My Theme"`.
2. Rename the inner file to `My Theme/My Theme.json` and set `"name": "My Theme"`.
3. Edit the colours and `meta.json` (author, description, licence, tags, optional previews).
4. Run `node scripts/build-index.mjs`, then `node scripts/validate.mjs` and `node --test scripts`.
5. Open a pull request with the new folder and the updated `index.json`.

Details are in [CONTRIBUTING.md](CONTRIBUTING.md). Only add palettes you wrote or whose licence allows it, and credit the author in the `author` field and in `CREDITS.md`.

## Layout and rules

`node scripts/validate.mjs` checks all of these. CI runs it on every push and pull request.

| Rule | Detail |
| --- | --- |
| Layout | `<Name>/<Name>.json`, `Name` exactly as in the `name` field. No path separators, no leading dot |
| Folder contents | `<Name>.json`, `meta.json`, listed previews, optional `.md`. Nothing executable |
| meta.json | Required fields: `author`, `description`, `source`, `credit`, `licence`, `tags`, `previews` |
| Previews | PNG or WebP, at most 300 KB each. Listed in `meta.json`, and every image must be listed |
| Size | File at most 64 KB |
| JSON | Valid, top level is an object |
| Name | `name` equals the folder name |
| Variants | At least one of `dark` or `light`, an object with hex `mSurface`, `mOnSurface`, `mPrimary` |
| Colours | Every other `m*` value is `#rgb` or `#rrggbb` (six digits preferred) |
| Slugs | Unique across the repo (lower-case, non-alphanumerics to `-`) |

## Theme file format

Three colours per variant are enough. Vaultdraw derives the rest. If `light` or `dark` is missing, it is generated.

```json
{
  "name": "My Theme",
  "author": "You",
  "dark": {
    "mSurface": "#171311",
    "mOnSurface": "#e6d5c2",
    "mPrimary": "#ea9875"
  }
}
```

Existing themes also set `mSecondary`, `mTertiary`, `mError`, `mOutline`, the `mOn*` and variant colours, and a `terminal` palette. Names follow Noctalia's palette format.

## index.json

One file for browsers and tools: a single fetch lists every theme. Regenerated by `node scripts/build-index.mjs`; CI fails if it is out of date. No timestamps.

It is an object `{ "schemaVersion": 1, "themes": [...] }`, themes sorted by name.

| Field | Meaning |
| --- | --- |
| `name` | Theme name |
| `slug` | Lower-case name, non-alphanumerics to `-`. Accents are not folded, so "Rosé Pine" is `ros-pine` |
| `path` | `<Name>/<Name>.json` |
| `meta` | `<Name>/meta.json` |
| `author`, `description`, `tags` | From `meta.json` |
| `source` | `noctalia`, `noctalia-community`, `cendre` or `contributed` |
| `credit`, `licence` | From `meta.json` |
| `modes` | Which of `dark` and `light` the file has |
| `swatch` | `{ "dark": [...], "light": [...] }`, each `[mSurface, mOnSurface, mPrimary]` as lower-case `#rrggbb`, only for modes that exist |
| `sha256` | Hex SHA-256 of the exact theme file bytes |
| `previews` | Preview paths relative to the repo root, may be empty |
| `homepage` | Optional URL |
